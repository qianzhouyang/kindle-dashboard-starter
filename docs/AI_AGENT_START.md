# 给朋友的 AI agent：从零部署指令

将下面整段复制给朋友自己的 AI agent。AI agent 应在朋友的电脑上执行，
所有设备、路径、网络地址和凭据都以朋友自己的环境为准。

```text
请帮助我把自己的 Kindle 做成本地看板，并实际完成适合我设备的部署与验证。
项目：https://github.com/qianzhouyang/kindle-dashboard-starter

先在我的电脑建立独立目录并 clone 项目，核对 origin，再读根 AGENTS.md、README.md、
docs/DEVELOPMENT.md 和 docs/VALIDATION.md；按任务读取其他教程，不一次加载全部历史。
记录本次使用的 commit。若目录已经存在，先检查修改和现有安装，避免覆盖我的文件。

第一阶段：在不连接或修改 Kindle 的情况下，创建项目虚拟环境、安装依赖，
使用全新的 KINDLE_DASHBOARD_DATA_DIR，在 127.0.0.1 启动控制台并验证三个模板、
文字编辑、图片选择/上传、保存重启和 1072×1448 的设备 PNG。
默认保持离线示例天气、USB 未配置；不要读取我其他应用的数据或索取账号 token。
遵守我电脑现有的端口/服务登记规则；不要自动安装系统服务、开机项或开放公网。

第二阶段：确认我的 Kindle 型号、固件、当前越狱/KUAL/USBNetwork 状态、备份与电量。
本项目的设备脚本只针对 PW3；如果不是 PW3，不直接执行这些脚本，先评估适配。
尚未越狱则读 docs/JAILBREAK_AND_BASE_SETUP.md，并重新核对当前上游兼容性。
已装好底座就跳过越狱，不重新清空。设备重置、固件操作、驱动/网络变更、OTA 系统改动，
以及覆盖已有设备安装前，先给出具体对象、备份和恢复办法，取得我对该动作的明确确认。
我的这段部署请求不构成对这些关键动作的预先同意。

第三阶段：按 docs/02-kindle-usb.md 配置我自己的专用 SSH 密钥和 USB 地址，
核验设备主机指纹。私钥留在电脑，不展示、不上传、不复用项目作者的身份文件。
备份已有安装后复制完整脚本和 KUAL 扩展，保持 LF，核对传输文件 SHA-256。
实际验证 USB 图片显示、90°/270° 朝向、短按返回阅读、触摸恢复、
拔线后 KUAL 缓存启动及再次返回阅读。需要我看设备或按键时，明确告诉我如何操作。
没有我的实机反馈，不把命令成功、测试通过或预览图当成物理设备验收。

第四阶段：只在我需要自动更新时读 docs/03-auto-refresh.md，
确认对应设备的 OTA 防护、局域网图像服务、Wi-Fi/RTC 前提后再配置。
不要绕过 OTA/主机指纹检查，不做公网转发；先解释联网图像无鉴权的访问范围。
无法满足前提就保留已验证的静态缓存方案，并明确剩余问题。

额度、电量和节点默认是手工/示例数据，不声称已经接入我的账号或监控；
真实天气需要我选择启用并提供自己的坐标，不把请求失败替换成假的实时天气。
保留这套猫图作为默认素材，也支持我上传自己的图片。

遇到错误先根据输出定位，不盲目重复清空、升级或覆盖。不要 push 到作者仓库，
不要上传我的配置、日志、密钥、设备标识或个人图片。
最后给我交付：使用版本、启动/停止命令、运行数据位置、已通过的验证证据、
需要我确认的实机结果、未完成项与恢复阅读/回滚方法。
请从只读环境检查和电脑端离线预览开始。
```

## 各阶段完成判据

| 阶段 | 应保留的验证结果 |
| --- | --- |
| 电脑端 | 启动命令、独立数据目录、编辑/保存结果、物理尺寸 PNG；示例与真实数据来源明确 |
| 底座 | 型号/固件及所选上游路径、备份检查、KUAL 可打开、自己的手工 SSH 可用 |
| 静态设备 | 本人确认显示方向与边缘、短按与触摸恢复、拔线缓存和返回阅读 |
| 自动更新（可选） | 本人确认完整更新周期、断网保留缓存、Wi-Fi/RTC 清理与阅读恢复 |

公开仓库的自动测试仅验证代码和模拟状态；不等于这些朋友设备的验收结果。
